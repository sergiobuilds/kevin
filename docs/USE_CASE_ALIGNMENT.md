# 10개 트랙에서 공통 실행기로 — 발산과 구현 범위

기준: [ROADMAP](../ROADMAP.md), [기여 안내](../CONTRIBUTING.md), 커밋 56af4e7.
이 문서의 확장안은 논의용이다. 10개 트랙의 시연·담당·완료 기준을 새로 결정하지 않는다.

## PR 1이 제공하는 공통 부분

- 기존 `DeviceAdapter`의 capabilities/apply/stop/status를 그대로 사용한다.
- capability 값은 bool/number/integer/string뿐 아니라 구역·좌표·관찰값을 담는 제한된 object/array도 받는다.
- 프로필이 선택한 기기의 이름·별칭·기능만 플래너에 보여준다. 토큰·주소·원시 패킷은 어댑터가 가진다.
- 계획 전체를 검증하고 대상별 설정을 확인한 뒤 순서대로 실행한다. 순서는 보장하지만 여러 물리 기기의 동시 성공·롤백은 보장하지 않는다.
- 미리보기와 실물 기준 상태를 분리한다. 중간 실패에는 완료한 동작, 실패/미확인, 미전송을 남긴다.
- 기본은 기존 크리스마스 쇼. 추가 직접 연결 예제는 WLED, 선택형 허브 예제는 HA 스위치/학습 IR이다.

### 구현한 것과 남은 것

이 PR이 10개 제품 드라이버나 카메라 자동 보정 루프를 완성하는 것은 아니다.
10개 트랙의 기능 형태를 가짜 어댑터로 검증하며, 실제 통신 구현은 각 트랙에서 담당한다.
WLED 예제는 명시한 구역에 값을 보내고 보고 상태를 읽는다. 진열대를 카메라로 인식하거나 위치를 추정하지 않는다.
기존 쇼 외 실물 시험 결과는 없다.

## 팀원이 연결하는 방법

1. `src/devices/<slug>.py`에서 기존 규격을 구현한다.
2. `Capability.schema`에는 제한된 JSON 값 형식과 범위를 선언한다. 객체는 properties/required, 배열은 items와 크기 상한을 넣는다. 임의 URL/셸/패킷 기능은 넣지 않는다.
3. 추가 제약은 선택적 순수 함수 `validate(changes)`에 둔다. 실행기는 모든 기기의 validate를 먼저 부른다. 이 함수에서 연결/파일 쓰기를 하지 않는다.
4. 어댑터를 `Registry([Device(...)])`에 등록해 테스트한다. CLI 프로필에는 registry의 명시적 팩토리에 이름을 추가한다. 자동 Python 파일 실행이나 네트워크 검색은 하지 않는다.
5. 동작 결과의 detail에는 공개 가능한 기능 상태만 담고 주소·토큰·원시 응답은 제외한다.
6. stop은 대기·반복·앱 소유 재생을 멈춘다. 이미 보낸 IR이나 타인이 바꾼 가전 상태를 임의로 되돌리지 않는다.

Luna PR은 이 공통 계획의 선택 플래너만 추가한다. 트랙별 통신 코드를 바꾸지 않는다.
