# KEVIN 본 앱 실행 결과와 정지 처리

기존 `docs/app` 화면과 `kevin_bridge.py`의 실행 경로를 보완합니다. PR #14의 확장 장치 데모와 main의 자유 LED 문구·점수판·작곡·게임 기능을 유지합니다. 공통 브리지·전송기·guardian을 변경하는 이유는 계획, 기기 실행, 관찰까지 같은 정지 요청을 적용하기 위해서입니다.

## 실행과 정지

`POST /say`는 작업 번호를 즉시 반환합니다. `GET /jobs/<job_id>`에서 계획 → 실행 → 관찰 → 완료 또는 실패를 확인합니다. 모델의 답변만으로 성공 표시를 하지 않습니다. 전광판 성공 뒤 라디오가 실패하면 두 결과를 따로 남깁니다. 장치가 ACK를 반환해도 `physically_verified=false`입니다.

새 요청이나 `POST /stop`이 이전 계획·경보·기기 작업·관찰을 취소합니다. 이미 발생한 물리 효과를 되돌린다고 보장하지 않으며, 정지는 별도의 장치 응답을 기다립니다. 정지 통신 실패는 화면에 `정지 확인 실패`로 표시합니다. 늦게 돌아온 이전 응답·음성·관찰 기록은 현재 요청을 덮어쓰지 않습니다. 네이티브 LED 문구·점수 명령도 취소를 감시합니다.

작곡과 장면을 같이 요청해도 캐럴을 중복 재생하지 않습니다. 음량 `0`은 그대로 보존하며, 음량만 바꾸는 요청은 재생을 시작하지 않습니다. 복합 요청은 필요한 장치 설정을 모두 검사한 뒤 실행합니다. 모델 출력은 타입·범위·허용된 동작을 검증합니다.

## 절약 모드: 오너가 선택한 정책

**움직임이 없다는 이유만으로 끄지 않습니다.** 서버의 방 카메라에서 새 프레임을 얻고, 사람이 없다는 명시적 판정이 30초 동안 이어질 때 중단을 요청합니다. 서로 다른 프레임이 필요하며, 관찰 간격이 12초를 넘거나 사람이 보이거나 판정이 불명확하면 확인 시간을 다시 시작합니다. 5초보다 오래 걸린 영상 판정은 사용하지 않습니다. 화면에서 주는 유휴 시간이나 임의의 이미지는 판단에 사용하지 않습니다.

영상 모델은 `person=true / false / null`을 반환합니다. 어둡거나 가려졌거나 확실하지 않으면 `null`이며 자동 동작을 보류합니다. 실제 방 전체의 부재를 보증하는 센서는 아니므로 카메라 사각과 실제 모델의 판정 품질은 현장에서 확인해야 합니다. 현재 웹 절약 모드는 설정된 OpenAI 영상 판정이 필요하고, 없으면 보류합니다.

구형 CLI `guardian.py`의 기본 HOG 탐지기도 사람을 못 찾았다는 이유로 부재를 확정하지 않습니다. 기본 탐지기로는 절약 자동 종료가 보류되며, 명시적 부재 판정을 제공하는 탐지기를 연결해야 합니다. 경보 화면·음성의 실제 경찰 신고처럼 보이던 표현도 경보 요청으로 수정했습니다.

카메라 읽기·인코딩에 실패하면 마지막 프레임을 비웁니다. 브라우저 사용자의 카메라로 자동 전환하지 않습니다. LED·라디오 상단 표시는 연결 검증이 아니라 설정 여부입니다.

## 결과와 관찰 기록

기존 `receipt.py`의 이미지 비교·Ed25519 서명을 재사용합니다. 실행 전과 실행 뒤 두 개의 새 프레임이 있을 때 관찰 기록을 만들고, 본 화면에서 전후 이미지와 기록을 엽니다. 관찰이 불가능해도 장치 응답은 표시합니다.

`changed/moving`은 화면 변화이며 소리·요청 의미의 성공을 증명하지 않습니다. 서명·이미지 해시는 기록 무결성 확인이며, 영수증 내부 공개키만으로 서명자 신원을 보증하지 않습니다. 최근 30개 작업의 허용된 영수증·이미지만 `/evidence`에서 읽을 수 있습니다. 런타임 기록은 `.runtime/bridge` 아래에 남습니다. 기존 로컬 브리지의 네트워크·인증 범위를 확장하는 배포 변경은 아닙니다.

## 검증과 남은 범위

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -q
node --check docs/app/app.js
git diff --check
```

가상 모델·장치·카메라로 계획 중 정지, 경보 중 정지, 늦은 관찰 취소, 부분 실패, 음량 0, 중복 재생 방지, 새 요청 우선, 오래된 카메라, 연속 부재와 불확실 판정을 검사합니다. 본 웹 화면의 작업 결과·관찰 기록·통신 실패와 데스크톱/390px 화면도 별도 브라우저 검증합니다. 실물 BLE·Windows 라디오·웹캠·실제 모델 API 호출은 이 검증에 포함하지 않습니다.

04–07 확장 장치를 본 채팅이 자연어로 자동 선택하는 기능은 후속 작업입니다. 기존 명시적 버튼·MCP 도구는 [확장 데모 안내](HACKATHON_DEMO.md)를 따릅니다. 새 오픈소스를 추가하지 않았으며, 기존 전광판 클라이언트 `pypixelcolor`, 영상·서명 라이브러리 및 자체 실행기를 재사용합니다. 출처·라이선스는 같은 안내의 출처 표를 유지합니다.
